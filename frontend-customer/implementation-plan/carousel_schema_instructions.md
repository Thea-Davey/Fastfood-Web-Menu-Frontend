# Database Schema and Connection Instructions: Home Carousel Banners

This document provides instructions on how to transition the home page banner carousel from frontend hardcoded data into the PostgreSQL database, and how to connect it to the customer frontend.

---

## 1. Database Schema Design

To manage banners dynamically, the backend team should create a new table called `public.banners`. This table will store the details of each banner, including its title, image URL, action link (where the user is redirected when clicking the banner), and fields to control order and visibility.

Run the following SQL statement in the database:

```sql
CREATE TABLE public.banners (
  id uuid NOT NULL DEFAULT uuid_generate_v4(),
  title text NOT NULL,
  image_url text NOT NULL,
  link text,
  display_order integer DEFAULT 0,
  is_active boolean DEFAULT true,
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  CONSTRAINT banners_pkey PRIMARY KEY (id)
);

-- Optional: Index on display_order and is_active for faster sorted querying
CREATE INDEX idx_banners_active_order ON public.banners (is_active, display_order);
```

### Column Explanations
*   `id`: Unique identifier for each banner.
*   `title`: The accessibility alt text and overlay text for the banner (e.g., `"Welcome to Blaine Wings!"`).
*   `image_url`: The hosting URL of the banner image.
*   `link`: The navigation route target on the frontend (e.g., `"/menu?category=Add on Dips"`). Can be `NULL` if the banner is not clickable.
*   `display_order`: Determines the sequence of banners in the carousel (ascending order, e.g., `1`, `2`, `3`).
*   `is_active`: Allows staff/admin to hide a banner without deleting it from the database.

## 3. Backend API Integration

The backend should expose a REST endpoint to serve active banners to the client.

### Endpoints Options

*   **Option A: Dedicated Endpoint (Recommended for simplicity)**
    `GET /api/banners`
    Fetches active banners sorted by `display_order`.
    *SQL Query used by backend:*
    ```sql
    SELECT id, title, image_url as "imageUrl", link 
    FROM public.banners 
    WHERE is_active = true 
    ORDER BY display_order ASC;
    ```

*   **Option B: Combined Landing Feed (Recommended for page performance)**
    Include the banners directly in the existing `GET /api/menu` or create a dashboard endpoint `GET /api/home-dashboard` that responds with banners, popular items, and best sellers together.
